Lay out a docs page

Build a documentation page from Nowind's shell lengths, its 12-column grid and four type roles. Every part on this page is the template you can copy.

Applies to Nowind 0.7.0

The frame

A docs page has five parts, always in the same place: a band and a header across the top, a sidebar on the left, the content in the middle and an on-page table of contents on the right. The frame fills the viewport, and only the sidebar and the content scroll.

The header is h-header tall and the sidebar w-sidebar wide. Both follow the base size, so they grow with the type from a phone to a wide screen.

Note

The frame keeps the header fixed and lets the sidebar and main scroll on their own. For a page that scrolls as a whole, make the header sticky top-0 and the sidebar sticky top-header with max-h-below-header, so it sits just under the header.

The grid

Inside main, content sits on Nowind's page grid: four columns on a phone, twelve from 768px up, with gap-grid between columns and px-grid at the edges. The article takes nine columns and the table of contents three; below 1280px the table of contents is hidden and the article takes all twelve.

WidthSidebarColumnsTable of contents
Under 768pxIn the menu4Hidden
768pxIn the menu12Hidden
1024px (lg:)w-sidebar12Hidden
1280px (xl:)w-sidebar12: 9 + 3Shown

The reading column

Prose stops at max-w-measure, 44 times the base size. The article is a tier-content region, so its section gaps and page padding are one and a half times the product rhythm and its measure grows with the tier's larger base size.

Tip

Put the tier on the article only. The header, sidebar and table of contents stay in the product tier, so they look the same on every page.

Four type sizes

A docs page needs four sizes and no more. Contrast between them is the hierarchy, so they sit far apart: a display size for the page title, a heading size for sections, the base size for reading and controls, and a small size for labels and code.

SizeClassesUsed for
Displaytext-display-smThe page title, once per page
Headingtext-heading-mdSection headings, each under a rule
Basetext-body-md, text-subtitle, text-title-smProse, subheadings, navigation and buttons
Smalltext-caption, text-label, text-kicker, text-mono-smMetadata, table heads, kickers and code

Weight, not size, separates a subheading from prose: text-subtitle is the base size at a semibold weight.

Callouts, code and tables

A callout is a coloured rule on the left, a word and a sentence. The colour codes the kind and the word says it, so the meaning never depends on colour alone.

Warning

A callout interrupts the reader. Use at most one per section.

A code block is a figure: the file name and language in a caption, the code in a pre that scrolls sideways rather than wrapping. Tables sit in a bordered box that scrolls on a narrow screen.

Navigation on a phone

Below 1024px the sidebar moves into a details element under the header. It opens and closes without a script, and the same list of links serves both places.
