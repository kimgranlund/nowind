Nowind site · one page, four kinds of content

Five page templates for every Nowind page

Today the site has four frames. Each new page copies one of them, so fixes made to one frame never reach the others. Each option below is a single template, shown on the same real content. Switch the page kind to see how each one handles a component, a colour specimen, a class list and a phone.

Page kind
Option A · after Vignelli

A black band on top, and every block hung from a label column

The site's sections sit in a black band, and the pages of the current section in a row below a heavy rule. Every block on every page has a label in the first three of twelve columns and its content in the other nine, so a component, a palette and a class list all share one grid.

KeepsOne scroll, one grid and one block shape on every page, including the showcase and the specimen.
Gives upA side index: you see only the current section's pages, so jumping to another section takes two steps.
Breaks whenA section has more pages than fit in one row: the 26 component pages scroll sideways in the sub-row.
Option B · after Gerstner

A programme of tiles: each kind of content takes a fixed number of units

The page is a six-unit grid of tiles on a tinted ground. A rule decides how many units each kind of block takes: a title four, a live example four, a list two, a swatch one, a class one. The section's other pages are tiles too, at the top.

KeepsSpecimens and examples read at a glance, and the same rule lays out any new kind of content.
Gives upReading order: prose and use-and-avoid lists get chopped into tiles of equal weight.
Breaks whenA list runs to a thousand classes: a thousand tiles is a wall, not an index.
Option C · after Müller-Brockmann

A fixed index of the whole site beside an asymmetric sheet

A narrow column lists every section and page, always open, with the current page marked. The sheet beside it has a narrow margin column for labels, set flush right, and one wide column for the content. On a phone the index folds into a bar.

KeepsEvery page is one click away, and it's closest to today's docs pages, so the least changes.
Gives upAbout a fifth of the width to the index, so live examples and wide tables have less room.
Breaks whenThe index outgrows the window (34 pages today): it needs its own scrolling, the one nested scroller left.
Option D · a ledger

Every page is one filterable table of name, rule and sample

Each page has a short head, a filter and one table. A component page lists its variants as rows, the specimen lists the colour steps, the class list lists the classes. Use and avoid become rows too. A breadcrumb replaces the menu.

KeepsThe most uniform option: one table pattern, one filter script, every page searchable the same way.
Gives upExplanation: guidance and prose have no natural place, and a component is never seen whole.
Breaks whenA page is mostly writing, like the guide, or an example needs room, like a dialog or a card.
Option E · list and one item

A list of the section's items, and one item at a time beside it

The section's items run down a list, and choosing one shows it alone in the detail pane: a component with its example, one colour step with its roles, one class with its declarations. Try it: the list in the mock works. On a phone the list and the item take turns.

KeepsFocus: one thing, full size, nothing competing; good for comparing a component's states.
Gives upOverview and find-in-page: you can't scan all twelve steps or every class at once.
Breaks whenThe list is long: a thousand classes in a narrow list is the nested scroller you just removed.
Depends onA small script on every page to swap the item and keep a link to it (assumed acceptable).

Reading

C for the frame, with A's label column inside the sheet, and D's table only for lists

I'd pick the index and sheet (C) as the one frame: a site of 34 pages needs every page one click away, and it's the smallest change from what works today. Inside the sheet I'd use A's rule of a label beside every block, so a component, a palette and a guide section all have the same shape. The class lists and the specimen tables would use D's filterable table as a block, not as the page. B and E show content well, but they fail on the 1,000-row class list, which the site has to carry.

Technical details 
Frame: doc_page() in scripts/templates.py would also render site/components.html, specimen.html and utilities.html (generated, not hand-written).
C maps onto existing classes: w-sidebar sticky top-header h-below-header overflow-y-auto (index), grid with a label column (new? or grid-cols-12 col-span-3 / col-span-9).
A's label column = md:col-span-3 / md:col-span-9 inside the article; no new class needed.
Mock colours are stand-ins for Nowind's slate neutral and blue accent-1, not the computed tokens.
